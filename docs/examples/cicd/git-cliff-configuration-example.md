# git-cliff Configuration Example

## Overview

This document provides a complete, annotated example of the `cliff.toml` configuration file used by CycleTime for automated release note generation. The configuration transforms conventional commits into beautifully formatted, categorized release notes with automatic linking to PRs and Linear issues.

## Configuration File Location

**Repository root**: `/cliff.toml`

Version controlled alongside code to ensure consistency across releases.

## Complete Configuration

```toml
# git-cliff Configuration for CycleTime CE
# Generates beautiful, icon-based release notes from conventional commits
# Documentation: https://git-cliff.org/docs/

[changelog]
# Changelog header (stripped in GitHub Release body)
header = """
# Changelog\n
All notable changes to this project will be documented in this file.\n
"""
# Template for each release entry
body = """
{% if version %}\
    ## [{{ version | trim_start_matches(pat="v") }}] - {{ timestamp | date(format="%Y-%m-%d") }}
{% else %}\
    ## [unreleased]
{% endif %}\
{% for group, commits in commits | group_by(attribute="group") %}
    ### {{ group | striptags | trim | upper_first }}
    {% for commit in commits %}
        - {% if commit.scope %}**{{ commit.scope }}**: {% endif %}\
            {{ commit.message | upper_first }}\
            {% if commit.links %} ({{ commit.links | join(separator=") (") }}){% endif %}\
    {% endfor %}
{% endfor %}\n
"""
# Footer with generation metadata
footer = """
<!-- generated by git-cliff -->
"""
# Trim whitespace for cleaner output
trim = true
# Use postprocessors for link generation
postprocessors = [
  # Convert PR numbers to GitHub links
  { pattern = '\(#([0-9]+)\)', replace = "([#$1](https://github.com/spiralhouse/cycletime/pull/$1))" },
  # Convert Linear issue IDs to Linear links
  { pattern = 'SPI-([0-9]+)', replace = "[SPI-$1](https://linear.app/spiral-house/issue/SPI-$1)" },
]

[git]
# Parse conventional commits
conventional_commits = true
# Don't filter out unconventional commits (put in "Other Changes")
filter_unconventional = false
# Split commits by newlines
split_commits = false
# Sort commits by oldest first
sort_commits = "oldest"

[remote.github]
# GitHub repository for link generation
owner = "spiralhouse"
repo = "cycletime"

# Commit Parsers - Priority Order Matters!
# Higher priority patterns must appear FIRST
[[commit_parsers]]
# PRIORITY 1: Breaking Changes (highest priority)
message = "^\\w+\\(.*\\)!:"
group = "🚨 BREAKING CHANGES"

[[commit_parsers]]
message = "^\\w+!:"
group = "🚨 BREAKING CHANGES"

[[commit_parsers]]
message = "^BREAKING[ -]CHANGE:"
group = "🚨 BREAKING CHANGES"

# PRIORITY 2: User-Facing Features (scope-based sub-grouping)
[[commit_parsers]]
message = "^feat\\(ui\\)"
group = "✨ User Interface"

[[commit_parsers]]
message = "^feat\\(dashboard\\)"
group = "✨ Dashboard"

[[commit_parsers]]
message = "^feat\\(mcp\\)"
group = "✨ MCP Integration"

[[commit_parsers]]
message = "^feat\\(api\\)"
group = "✨ API"

[[commit_parsers]]
message = "^feat"
group = "✨ Features"

# PRIORITY 3: Bug Fixes (scope-based sub-grouping)
[[commit_parsers]]
message = "^fix\\(mcp\\)"
group = "🐛 Bug Fixes - MCP"

[[commit_parsers]]
message = "^fix\\(ui\\)"
group = "🐛 Bug Fixes - UI"

[[commit_parsers]]
message = "^fix\\(cache\\)"
group = "🐛 Bug Fixes - Cache"

[[commit_parsers]]
message = "^fix"
group = "🐛 Bug Fixes"

# PRIORITY 4: Performance & Security
[[commit_parsers]]
message = "^perf"
group = "⚡ Performance Improvements"

[[commit_parsers]]
message = "^security"
group = "🔒 Security"

# PRIORITY 5: Developer-Facing Changes
[[commit_parsers]]
message = "^docs"
group = "📚 Documentation"

[[commit_parsers]]
message = "^refactor"
group = "♻️ Code Refactoring"

[[commit_parsers]]
message = "^test"
group = "🧪 Testing"

# PRIORITY 6: Infrastructure Changes
[[commit_parsers]]
message = "^build(?!\\(deps\\))"
group = "📦 Build System"

[[commit_parsers]]
message = "^ci"
group = "⚙️ Continuous Integration"

# PRIORITY 7: Dependencies (separate group)
[[commit_parsers]]
message = "^build\\(deps\\)"
group = "📦 Dependencies"
default_scope = "deps"

# PRIORITY 8: Filtered Out (no release notes)
[[commit_parsers]]
message = "^chore"
skip = true

[[commit_parsers]]
message = "^style"
skip = true

# Catch-all for unconventional commits
[[commit_parsers]]
message = ".*"
group = "📝 Other Changes"
```

## Configuration Sections Explained

### 1. Changelog Template

**Purpose**: Defines the Markdown structure of release notes

**Key Elements**:
- `header`: Stripped when using `--strip header` flag (CI usage)
- `body`: Tera template for grouping and formatting commits
- `footer`: Generation metadata comment
- `trim`: Removes extra whitespace for cleaner output

**Template Logic**:
```tera
{% for group, commits in commits | group_by(attribute="group") %}
    ### {{ group | striptags | trim | upper_first }}
    {% for commit in commits %}
        - {{ commit.message }}
    {% endfor %}
{% endfor %}
```

Groups commits by their assigned `group` from commit parsers, then iterates through commits in each group.

### 2. Postprocessors

**Purpose**: Transform text patterns into clickable links after changelog generation

**PR Link Postprocessor**:
```toml
{ pattern = '\(#([0-9]+)\)', replace = "([#$1](https://github.com/spiralhouse/cycletime/pull/$1))" }
```

- **Input**: `(#171)`
- **Output**: `([#171](https://github.com/spiralhouse/cycletime/pull/171))`

**Linear Issue Postprocessor**:
```toml
{ pattern = 'SPI-([0-9]+)', replace = "[SPI-$1](https://linear.app/spiral-house/issue/SPI-$1)" }
```

- **Input**: `SPI-839`
- **Output**: `[SPI-839](https://linear.app/spiral-house/issue/SPI-839)`

### 3. Git Configuration

**Key Settings**:
- `conventional_commits = true`: Parse conventional commit format
- `filter_unconventional = false`: Include non-conventional commits in "Other Changes"
- `sort_commits = "oldest"`: Chronological order within groups

### 4. Commit Parser Priority

**Priority Order** (must be maintained):

1. **Breaking Changes** - Always appear first
2. **Features** - Scope-based sub-grouping (ui, dashboard, mcp, api)
3. **Bug Fixes** - Scope-based sub-grouping (mcp, ui, cache)
4. **Performance & Security** - High-impact changes
5. **Developer-Facing** - Documentation, refactoring, testing
6. **Infrastructure** - Build and CI changes
7. **Dependencies** - Separate collapsed section
8. **Filtered** - chore, style (never shown)

**Why Priority Matters**: git-cliff uses **first match wins**. If breaking changes parsers appear after feature parsers, breaking changes would be categorized as features.

## Icon Reference

| Icon | Category | Commit Type |
|------|----------|-------------|
| 🚨 | BREAKING CHANGES | `feat!:`, `fix!:`, `BREAKING CHANGE:` |
| ✨ | Features | `feat:`, `feat(scope):` |
| 🐛 | Bug Fixes | `fix:`, `fix(scope):` |
| ⚡ | Performance | `perf:` |
| 🔒 | Security | `security:` |
| 📚 | Documentation | `docs:` |
| ♻️ | Refactoring | `refactor:` |
| 🧪 | Testing | `test:` |
| 📦 | Build/Dependencies | `build:`, `build(deps):` |
| ⚙️ | CI/CD | `ci:` |
| 📝 | Other | Unconventional commits |

## Scope-Based Sub-Grouping

**Configuration Pattern**:
```toml
[[commit_parsers]]
message = "^feat\\(ui\\)"
group = "✨ User Interface"

[[commit_parsers]]
message = "^feat\\(dashboard\\)"
group = "✨ Dashboard"

[[commit_parsers]]
message = "^feat"
group = "✨ Features"  # Catch-all for feat without specific scope
```

**Result**:
```markdown
### ✨ User Interface
- **ui**: Implement settings page
- **ui**: Add navigation menu

### ✨ Dashboard
- **dashboard**: Implement lazy loading

### ✨ Features
- Implement general feature
```

## Common Customization Scenarios

### Adding New Scope Group

**Scenario**: You want GraphQL commits in separate section

**Solution**: Add parser before generic feature parser
```toml
[[commit_parsers]]
message = "^feat\\(graphql\\)"
group = "✨ GraphQL API"

[[commit_parsers]]
message = "^feat"
group = "✨ Features"
```

### Changing Icons

**Scenario**: You prefer different emojis

**Solution**: Edit group names
```toml
[[commit_parsers]]
message = "^feat"
group = "🎉 New Features"  # Changed from ✨
```

### Filtering Additional Commit Types

**Scenario**: You want to exclude `ci:` commits

**Solution**: Add skip rule
```toml
[[commit_parsers]]
message = "^ci"
skip = true
```

### Grouping Dependencies by Type

**Scenario**: Separate Kotlin, Ktor, and Gradle dependencies

**Solution**: Add specific parsers before generic deps parser
```toml
[[commit_parsers]]
message = "^build\\(deps\\).*kotlin"
group = "📦 Dependencies - Kotlin"

[[commit_parsers]]
message = "^build\\(deps\\).*ktor"
group = "📦 Dependencies - Ktor"

[[commit_parsers]]
message = "^build\\(deps\\).*gradle"
group = "📦 Dependencies - Gradle"

[[commit_parsers]]
message = "^build\\(deps\\)"
group = "📦 Dependencies - Other"
```

## Breaking Change Detection

**Supported Formats**:

**Format 1: Type with `!` suffix**
```
feat(api)!: remove deprecated endpoint
```

**Format 2: Type-only with `!`**
```
feat!: breaking change
```

**Format 3: Footer with `BREAKING CHANGE:`**
```
feat(api): update authentication

BREAKING CHANGE: JWT tokens now required for all endpoints
```

**Regex Patterns**:
```toml
# Matches: feat(api)!:
{ message = "^\\w+\\(.*\\)!:", group = "🚨 BREAKING CHANGES" }

# Matches: feat!:
{ message = "^\\w+!:", group = "🚨 BREAKING CHANGES" }

# Matches: BREAKING CHANGE: or BREAKING-CHANGE:
{ message = "^BREAKING[ -]CHANGE:", group = "🚨 BREAKING CHANGES" }
```

## Testing Configuration

**Local Testing**:
```bash
# Test current configuration
git-cliff --config cliff.toml --latest --strip header

# Test with verbose output
git-cliff --config cliff.toml --latest --strip header -vv

# Test specific tag range
git-cliff --config cliff.toml v0.1.0..v0.2.0
```

**Validation Checklist**:
- [ ] Commits categorized correctly
- [ ] Icons displayed
- [ ] PR links generated
- [ ] Linear links generated
- [ ] Breaking changes appear first
- [ ] Dependencies grouped separately
- [ ] Chore/style commits excluded
