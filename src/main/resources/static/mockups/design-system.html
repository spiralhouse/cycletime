CycleTime Design System

Foundation Components & Design Tokens

Introduction

This design system establishes the visual language and component library for the CycleTime dashboard. It prioritizes developer experience, information density, accessibility, and professional credibility.

Design Principles

  • Function Over Form - Every design choice serves a user need
  • Information Density - Maximum relevant information without overwhelming
  • Predictable Patterns - Consistent components reduce cognitive load
  • Accessible by Default - WCAG 2.1 AA minimum compliance
  • Performance Conscious - Fast loading matters more than visual complexity

  • role="search" Search functionality
  • role="contentinfo" Footer information
Interactive Elements
  • aria-label Descriptive labels for icons
  • aria-describedby Link errors to form fields
  • aria-expanded Dropdown/accordion state
  • aria-live Dynamic content updates

Semantic HTML Structure

Proper semantic HTML provides natural accessibility:

  • ✓ <header>, <main>, <nav>, <footer> for page structure
  • ✓ <button> for interactive actions (not <div>)
  • ✓ <label> associated with all form inputs
  • ✓ Proper heading hierarchy (h1 → h2 → h3)
  • ✓ <article> for self-contained content blocks

4.4 Developer Testing Checklist

Ensure accessibility compliance when using design system components

Manual Testing

1. Keyboard Navigation
  • All interactive elements reachable via Tab key
  • Focus indicators clearly visible on all elements
  • Tab order follows logical reading order (top-to-bottom, left-to-right)
  • No keyboard traps (can Tab in and out of all components)
  • Buttons activate with Enter and Space keys
  • Modals/dropdowns close with Escape key
2. Screen Reader Testing
  • Test with NVDA (Windows) or VoiceOver (macOS)
  • All images have meaningful alt text
  • Form errors announced to screen readers
  • Dynamic content updates announced (aria-live)
  • Skip links present ("Skip to main content")
3. Visual Testing
  • Test at 200% browser zoom (text remains readable)
  • Verify color contrast with browser DevTools
  • Check focus indicators on all interactive elements
  • Test with Windows High Contrast mode
